## Summary

The book title is currently hardcoded as "[name]'s Tale". It should be dynamically generated by the LLM, evolving as the story progresses — just like chapter titles are already generated dynamically.

## Issues from v1 feedback

- "The book title is now hard coded as '[name]'s tale' but should be generated"
- "After each chapter the title should be updated to reflect the current 'full book title'"
- "Just like each chapter gets a live generated name"

## Design

### Book title generation

The LLM generates a book title at two moments:
1. **After the first chapter** — once the story's direction is established
2. **After each subsequent chapter** — the title evolves to reflect the story's current arc

**Prompt addition to the system prompt or chapter finalization:**

```
[BOOK_TITLE]
A title for this book — evocative, literary, 2-6 words. 
Reflects the current story arc, not just the current chapter.
Examples: "The Sunken Archive", "Where Shadows Gather", "The Last Cartographer"
```

The title is stored in `session.campaign_meta["book_title"]` and updated after each chapter.

### Chapter title refinement

Chapter titles already work well. Keep the current system but ensure:
- Chapter titles are unique within a book
- Chapter titles reflect the chapter's content, not just the location
- The LLM has access to previous chapter titles to avoid repetition

### Metadata structure

```python
session.campaign_meta = {
    "book_title": "The Sunken Archive",      # updated per chapter
    "book_subtitle": "A tale of Lyra",       # set once, optional
    "character_name": "Lyra",
    "genre": "mystery investigation",        # from Session Zero
    "tone": "mysterious",
    "total_chapters": 5,
    "total_passages": 23,
    "word_count": 12450,                     # estimated
    "listening_time": "47 minutes",          # estimated from audio
}
```

### Frontend display

- **Top bar:** Shows the dynamic book title (left), chapter name (center)
- **Library:** Shows the dynamic title on each story card
- **Settings:** Shows full metadata (title, character, genre, chapter, passage count, word count, listening time)

### "Passage" terminology everywhere

From feedback: "in the bottom bar it's still called 'turn' > change it everywhere to 'passage'"

Search and replace in all user-facing strings:
- "Turn 5" → "Passage 5"
- "turn_id" in URLs can stay (internal)
- "audio_turn_id" can stay (internal)
- Any visible label must say "passage"

### Optional turn marks

From feedback: "there should be a setting to turn them back on if the user wants to see them"

Add a setting: "Show passage numbers" (default: off)
- When ON: small passage numbers appear at the start of each passage (e.g., "§5")
- When OFF: no visible passage numbers

### Word count and listening time

Track:
- Total word count across all passages (sum of segment text lengths / 5)
- Total audio duration (sum of all segment audio durations)
- Display in Settings: "12,450 words · 47 minutes of narration"

### Story arc tracking

For the world view (v1.7) and for title generation, track the story's arc:
- **Act 1** (chapters 1-3): Introduction, world-building, inciting incident
- **Act 2** (chapters 4-7): Rising action, complications, midpoint revelation
- **Act 3** (chapters 8+): Climax, resolution

The book title can reflect the current act:
- Act 1: "The Sunken Archive" (mysterious, setting-focused)
- Act 2: "Beneath the Surface" (deepening, conflict-focused)
- Act 3: "What Lies Below" (climax-focused)

This is optional and subtle — the LLM handles it naturally if given the right context.

## Implementation plan

1. Add `[BOOK_TITLE]` section to the LLM response format
2. Parse it in `parse_response()` or `finalize_passage()`
3. Store in `session.campaign_meta["book_title"]`
4. Include in API responses (`book_title` field)
5. Frontend: update top bar title from `data.book_title`
6. Frontend: add "Show passage numbers" setting
7. Replace all user-facing "turn" with "passage"
8. Track word count and listening time in session metadata
