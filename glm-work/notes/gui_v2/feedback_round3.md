# GUI Feedback Round 3 — Control/Tab UI

Agent record of user feedback from round 3 (not human-typed lines).

## Bottom bar tab
- Bottom bar tab is hidden behind the audio bar — needs to be on top of it
- Want different options for opening/closing that is always visible but not too attention-grabbing
- Options to explore: toggle in top bar, something on the side of the screen, integrated with audio bar (though that seems weird)
- Open to better ideas

## Side panel toggle buttons (☰ and ⚙)
- Should vertically stick to the side bar, not move into the top bar when it is open
- Stay below the top bar, vertical position relative to the side bar
- Try as little horizontal tabs / half-circle outlines, attached as if it's a little bookmark on the side panel — like a little strip or tab you can pull out

## Top bar hide button (▴ in top bar)
- Nice, but maybe just put it in the tab — the tab can stay visible as a use-cue also when the topbar is visible
- Or if you have another idea to make it more like a fixed UI element, feel free to show me

## Top bar tab (▾)
- Perfect, just make it move down with the top bar when it appears

## Bottom bar hide button (▾ in bottom bar)
- Works nicely, but could be more visible or with similar styling to the new tab layout for the top bar

## Bottom tab (▴ at center-bottom)
- Not clearly visible because it's hidden behind the audio bar

## Hide both bars
- This is perfect — no intrusive GUI elements when the user just wants to read
- But we do need a few simple elements on the sides, unobtrusive, but still use-cues for opening and closing all side/top/bottom bars

## Audio bar
- Can collapse to just a line — without any bar at all when collapsed
- On the far left: a breathing triangle / play / pause / stop button stays visible
- On the far right: a little tiny tab or triangle to open the audio bar to full size again
- Clicking on the audio line should open up the full size audio bar, NOT change audio playback position

## Input area
- Spacing below the input area should be higher, so it is more visible "in screen" and not completely at the bottom

## Request
- Make 5 new variants with different approaches to the control/tab UI
- Add 3 creative / out-of-the-box variants (book-related or inspired GUI elements)
- Update index page explaining the differences
